## D7：recursiveReverseMappedType ★已隔离到「条件半边 + 同别名双形态分歧」

**r32 状态**：compiler 唯一 FAIL。官方零错误；我们 2 错（2322 + 2345）。

**二分结论**（/tmp/rr6、/tmp/rr7 最小复现）：
- **元组递归半边已通过**：`type R2<T> = ['marker', ...R2<T>[]]` 在泛型
  函数间传递/调用/返回全链零错误（rr7）
- **条件半边失败**：`type R1<T> = T extends unknown[] ? {} : { [K in
  keyof T]?: R1<T[K]> }` 在「另一泛型函数内调用」时双错（rr6）；
  同样代码在非嵌套泛型上下文零错误（rr1/rr4）
- **关键现象——同别名双形态分歧**：同一个 `R1<T>[]`，实参 `l` 的注解
  解析为**延迟条件**（显示 `T extends unknown[] ? object : {...}`），
  而 join 的参数注解解析为**塌缩映射**（显示 `{[error in string]: ...}`，
  error 型泄漏）。两形态结构比较必然失败 → 2345；返回位同理 → 2322
- 塌缩时的具体退化：free T 的 `T extends unknown[]` 判 false →
  `keyof T`（无约束）→ 近似为 string → 映射类型参数显示为 error →
  `{[error in string]: {[error in never]: error}}`

**下轮攻坚路径**（按优先级）：
1. 找到 join 参数注解的解析走点（签名构建期 vs l 注解的检查期惰性解析），
   对齐两路径的延迟决策（free check type → 必须延迟，Go getTypeFrom
   ConditionalTypeNode 语义）——疑似签名构建路径在某处急切求值了条件体
2. 若 1 不可行：relater 对「同别名符号+同实参」的两实例加恒等快路径
   （alias symbol ptr 相等 + type_arguments 逐位 ptr 相等 → related）
3. error 型显示（`[error in string]`）顺带核对 type printer 的映射参数名
