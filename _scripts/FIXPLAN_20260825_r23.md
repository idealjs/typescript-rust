## Fix 8（新根因，Fix 4 的使能项）：可选参数类型并入 undefined

**Go 权威**：`assignParameterType`（checker.go:10455）：
`links.resolvedType = addOptionalityEx(t, isProperty=false,
declaration.Initializer()==nil && isOptionalDeclaration(declaration))`；
`isOptionalDeclaration` = 仅问号（utilities.go:299）；`addOptionalityEx` =
strictNullChecks 时 `getOptionalType(t)` = `T | undefined`。符号类型即含 undefined，
签名参数（存符号）与函数体引用（getTypeOfSymbol）全部继承。

**我方缺口**：typenode.rs:2853 签名构造里 `param_type`（注解直取）与
checker.rs `resolve_symbol_declared_type_on_demand` ParameterDeclaration 分支
均无折叠。可选属性路径已有（探针 p5/p6 证）。

**修法**：
1. typenode.rs 签名构造（~2853）：`question_token && initializer.is_none() &&
   self.strict_null_checks` → `param_type | undefined`
2. resolve_symbol_declared_type_on_demand 的 ParameterDeclaration 分支同折
3. 单测：p4 形态 2322、p3 形态 18048、p1 形态（&&= 后 2722）、p7 形态保持 0 错

**风险面**：strict 族大量用例会首次见到参数 undefined——方向与官方一致，
预期净转绿；r24 sweep 验证。**Fix 4 的 la5 四错在本修复后才可能通**（f 类型
含 undefined 是 2722/18048 的前提；后置窄化/RHS 帧/对象位置门控已就位）。

## Fix 7a：static 成员内 `this` = 构造器类型

**Go 权威**：`tryGetThisTypeAtEx`（checker.go:12216-12225）：容器父为 class-like
时 `IsStatic(container) → t = getTypeOfSymbol(classSymbol)`（类符号的类型 =
构造器/静态侧），否则 instance thisType。

**我方**：checker.rs:3903 ThisKeyword 分支恒取 this_type_stack（实例类型）。
修：从 node 沿 parent 上溯至 enclosing_class_stack.last()，途经首个类成员带

外层（Go 先跳箭头）——上溯时直接穿过箭头/函数即可（找的是类成员边界）。

## Fix 7b：box 表观类型缺 heritage 成员

**我方**：`boxed_apparent_type_of_primitive`（checker.rs:5857）扫描所有

**修法**：扫描时对带 heritage 子句的声明，解析基接口（with_declaring_file_context

## Fix 7c：交集源含类型参数被塌缩

最小复现 /tmp/p10.ts：`T & {otherProperty} → {common,other}` 我方把源塌缩成
T 约束第一成分 FirstInterface 再查属性 → 假 2345 "Property 'otherProperty' is
missing in type 'FirstInterface'"。Go 对交集源做结构比较：属性查
`getPropertyOfType(intersection, name)`——任一成分有即有（T 的表观类型 =
约束联合，两成分均有 commonProperty）。修：relater 的交集→对象目标属性检查
不走"源类型参数→约束替换"（该替换只在源**本身**是类型参数时适用）。需先用
TSOX_DEBUG_INFER 定位具体替换点。
