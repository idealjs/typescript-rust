## A. logicalAssignment5（TS7006 误报族）— 上下文参数计数断点

现象（CLI 探针，target/debug/tsox 当前码）：
- `cb((a) => a)`（declare function callee）✓ 无 7006
- `arr.map(a => a.length)` ✓
- `const g: (a:number) => void = (a => a)` ✗ 7006 —— **注解初始化器路径断**
- `f = (a => a)` / `f ??= (a => a)`（f 为函数类型参数）✗ 7006 —— **赋值 RHS 路径断**
- `function h(f: (a:number)=>void) { f((a) => a); }` ✗ —— **参数类型 callee 的实参上下文断**

机制（checker.rs ~13800）：arrow 的 `contextual_param_count` =
`call_arg_arrow_context`（调用实参路径，contextual_param_count_for_arg：
`get_type_of_node(callee) → as_structured → call_signatures().first()`）或
`get_contextual_type(node)`（初始化器/二元 RHS 路径）→ 结构化 → 首签名参数数。
两条路径对「函数类型注解/参数符号类型」都返回 0——断点疑在：
(a) `get_contextual_type_for_initializer_expression` 返回的 FunctionTypeNode 解析
    结果 `as_structured()` 是否带 call_signatures（create_function_or_constructor_
    type 的 TypeData 形态）；
(b) `contextual_param_count_for_arg` 对 callee=Identifier（参数符号）的
    `get_type_of_node` 是否走流分析返回了非声明态。
调试入口：TSOX_DEBUG / 临时 eprintln + 单用例 worker（r15 结束后）。
官方期望（target=esnext 等）：`f ??= (a => a)` 后 `f(42)` 报 2722（??= 后仍
possibly undefined）/bar* 形态 18048——还缺 ??=/||=/&&= 赋值后的确定赋值流分析。

## B. nodeModulesImportAttributesModeDeclarationEmit1（欠报 2305）

官方 node16：import attributes 不支持 → 每条 with 语句报 2823 ✓（我们已对）；
之后解析**忽略属性**走默认链（/index.ts implied CJS → require 条件 →
require.d.ts）→ 第二条 import 的 ImportInterface 缺失 → TS2305 (7,14)。
我们：报 2823 后模块解析被跳过（或带坏属性模式解析失败静默）→ 无 2305。
修：checker 2823 分支后不跳过成员解析；解析用默认 mode（implied format）。
