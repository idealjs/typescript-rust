## D1 lib.dom 接口 heritage 合并在环上静默丢失（jsxJsxs 家族 FAIL 的根因）

**现象**（CLI 实证）：
- `declare const a: HTMLAnchorElement; const e: Element = a;` → TS2739 缺 ~150 个
  Element 成员；`HTMLElement → Node` 同样失败；任何跨 2 层 lib.dom 继承的赋值失败
- `h.id`/`h.classList`（Element 成员）TS2339，但 `h.accessKey`（HTMLElement 自有）
  正常 → HTMLElement 被缓存为「仅自有成员」形态
- 用户文件 3 层链、本地 .d.ts、多基类全部正常 → 仅 bundled lib 触发

**根因链**：
1. lib.dom 稠密依赖图（Element.member parentElement: HTMLElement；HTMLElement
   extends Element, ...）首次解析顺序不定。当 HTMLElement 的首次完整解析发生在
   Element 解析中途（例：Element → member HTMLSlotElement → HTMLElement →
   base Element[进行中]）→ resolve_interface_type_ex 顶部环守卫返回 errorType
2. errorType 带 Any 旗标 → merge_interface_type_with_base 首行
   `if base.flags.contains(TypeFlags::Any) { return derived; }` **静默跳过合并**
3. 结果（仅自有成员）写入 type_alias_links.declared_type 缓存，永久污染
4. react16.d.ts 的 `DetailedReactHTMLElement<P,T extends HTMLElement> extends
   DOMElement<P,T>`（T extends Element 约束）→ TS2344 ×~70/文件 → jsxJsxs 家族
   每用例 865 行错误（多数被分诊掩盖，SubstitutesNames 未登记 → FAIL）

**修复方向**（Go 忠实：checker.go resolveDeclaredMembers / resolveBaseTypes——
成员惰性解析，接口类型创建不递归解析成员类型）：
- 首选：把「自有成员构建」与「heritage 合并」分成两个阶段。own 阶段禁止触发
  接口解析递归的环守卫误伤（成员类型引用按现状逐成员退化可接受）；heritage
  合并阶段在 base 返回 errorType（环守卫）时**不缓存**结果——记录 pending，
  base 完成后重合并；或 merge 时递归确保 base 自身的 bases 已合并
  （heritage-only 栈防环）
- 兜底验证用例：/tmp/jsxlib/{k,t,w,x,z}.ts 系列 + react16.d.ts 0 错误
- 预期消除：jsxJsxs 全族 865 行错误、domTests 族的 2339/2739/2344 误报

## D2 import/export 定型子系统缺失（命名导入静默 any）

**现象**（CLI 实证，tsgo-ref 对照）：
- `import { shown } from "./b2"; const s: string = shown;` → 官方 TS2322，我们 0 错误
- `import { hidden } from "./b2"`（未导出）→ 官方 TS2459，我们静默
- `import App from "./b"`（export default function）→ 官方 () => number，我们 any

**根因**：
- type_of_imported_symbol（checker.rs:10023）只认 ImportSpecifier 声明；
  default import（ImportClause.name）不在内 → None → any
- binder 从不把顶层导出声明放进文件符号 exports（exports.insert 仅 3 处特殊
  场景）；namespace_member_recursive 靠 members 回退才让命名导入勉强工作，
  但 type_of_imported_symbol 的 resolved_type 查询仍常落空
- export default function/class：binder 无 Go declareSymbolEx 的
  isDefaultExport → name="default" 改名逻辑 → exports["default"] 永不存在

**修复方向**：
1. type_of_imported_symbol 补 ImportClause 分支（导入名 "default"）
2. binder declare_symbol：模块容器 + Export+Default 修饰符 → 同符号额外插入
   exports["default"]（Go declareSymbolEx 语义，单符号架构下双注册）
3. 顶层导出声明进文件符号 exports（Go declareModuleMember 两符号制的近似）
4. （后续轮）checkImportDeclaration 的导出性/缺失检查（TS2459/TS2305）

## D4 新式 CJS transform（F8 遗留，transpile 22 例 accepted-diff 主根因）

官方：`"use strict";\nObject.defineProperty(exports, "__esModule", { value: true });\nexports.default = App;\nfunction App()...`
我们：无 __esModule 前导、赋值在声明后。

挂载）已使 exports.default 赋值生成，差前导与顺序。
