### 修法（保持单符号模型，不动 binder 主路由，全部改 checker 侧查询）

`module_member_lookup`（checker.rs:15554）重做为 Go getExportsOfModule 的
符号级等价物，按序：

1. **exports 直查**（现状保留）
2. **default 条目补全查询**：名字 == "default" 时，除 exports 外扫模块
   符号声明节点（SourceFile / ModuleDeclaration）语句表：
   - ExportAssignment（非 export=）→ Found（`export default <expr>`）
   - 带 Default 修饰符的 class/function/interface 声明 → Found
   （binder 侧不补条目——避免扰动既有 members/locals 语义；查询侧识别
   Go declareSymbolEx 的 `isDefaultExport` 等价形态）
3. **ExportSpecifier 补全查询**：exports/成员表未命中时，扫语句表中
   ExportDeclaration 的 export_clause elements：ExportSpecifier 的
   导出名（property_name ?? name，注意 ModuleExportNameIsDefault：
   `as default` 的 name 是 "default"）匹配 → Found。转发子句
   （`export {X} from "m"`）不在本地补——由 4 的星链/转发解析处理：
   实际上 Go 把转发子句也作为 exports 别名（alias 分支），所以转发
   子句同样 → Found（符号即别名，目标未解析不影响存在性）
4. **星链递归**：模块的每个 `export * from` 声明（语句表扫描，不依赖
   binder 的 export* 符号——但优先用 exports["export*"] 的 declarations
   收集），解析目标模块（specifier 相对该文件，resolve_external_module_path
   + ambient 回退）→ 递归 module_member_lookup（深度上限 8，visited 集合
   防环）。星链不导出 "default"（Go extendExportSymbols 跳过 default）——
   递归查询名 == "default" 时直接跳过星链分支
5. **ambient 模块体**：模块符号的声明是 ModuleDeclaration 时，查
   symbol_map.locals[module_node.id()]（隐式导出语义）→ 命中 → Found。
   同样适用于 SourceFile 符号缺自链的兜底（现状已有）
6. **export= 目标解析重做**：exports["export="] 的符号声明为
   ExportAssignment 且表达式是 Identifier/QualifiedName 时：在**声明文件**
   上下文里 resolve_qualified_symbol(表达式) → 目标符号（命名空间），
   查 target.exports/members（ambient 命名空间再查 locals）；
   `export = alias`（alias 是 `import X = NS` 别名）经
   resolve_alias_base 的 ImportEqualsDeclaration 分支已可解，衔接即可
7. **synthetic default**：名字 == "default" 且以上全 miss：
   - 模块是声明文件（.d.ts）或 ambient 模块：无 syntactic default
     （2 的扫描即 null）且无 "__esModule" 导出 → Found
     （Go canHaveSyntheticDefault 宽容分支；TS 源文件不走此分支）
   - 非声明 TS 文件：有 export= → Found（hasExportAssignmentSymbol）
   esModuleInterop/allowSyntheticDefaultImports 关闭时的精确 mode 规则
   （usageMode/targetMode）先不引入——观察 r22 是否有反例用例
