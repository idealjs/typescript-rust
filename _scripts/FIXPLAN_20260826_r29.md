## D3-sig：genericClassWithObjectTypeArgsAndConstraints（方法位类型参数遮蔽）★已修复（r30 轮）

**最小复现**（/tmp/probe-d3/d3b.ts，现有二进制即复现）：
```ts
class G<T extends { x: string }> {
    foo<T extends { x: string }>(t: X<T>, t2: X<T>) { ... }
}
var g: G<{ x: string; y: string }>;
g.foo(new X<C>(), new X<D>());   // TS2345: X<C> 不兼容 X<{x;y}> ← 参数的 T 用了类的 T
```
改名 `foo<M>` 后零错误 → 纯同名遮蔽问题。

**根因**：方法签名的参数注解 `X<T>` 在**调用点**惰性解析时，scope 栈不含方法节点，
动态走查落到类符号 members 的 T（类 T 已实例化为 {x,y}）。方法自己的 T 在
MethodDeclaration 符号的 members（binder：MethodDeclaration 是 HAS_LOCALS 容器，
parent_symbol 路由进成员表）。

**修法**：签名构建/解析（build_signature_from_declaration 及惰性参数解析路径）在解析
参数/返回注解前 push 方法/函数声明节点（同 FunctionTypeNode 的 push_scope(node) 模式；
typenode.rs:2718 附近有现成范式）。对照 localTypes1 的 with_declaring_file_context 链修复
（本方法节点已在链集合里，但签名构建不走 with_declaring_file_context）。

**连带**：conformance 只差 Class 命名空间块（Interface 块通过）——接口方法签名走
build_interface_type_from_members 已有正确 push（1284 行 push_scope(member)）。
