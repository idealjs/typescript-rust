## D7 ✓ 已修复（本轮四组件）

r32 后对 rr6/exp_c/exp_g/b2~b6/exp_disp 十余个最小复现做官方 tsgo 二分对比，
结论：**官方对本例的放行通道在「推断层」而非「关系层」**——
`<Y>(c: C<Y>)` 接收 `C<X>` 实参时，Go inference.go ~L79 对**同别名符号**
的 source/target 直接互推断别名类型参数（Y:=X），两边修成同一延迟实例后
关系判定平凡通过。b5（延迟→已解析假支目标=2）官方**报错** '1|2'→'2'，
证明默认约束联合并不放宽具体目标。四组件：

1. **三态条件解析判定**（relater.rs `resolve_conditional_type_with_check`）
   移植 Go getConditionalTypeInstantiation checker.go ~L24440：
   definitely-false = !extends∈anyOrUnknown && (check is any ||
   !assignableTo(permissive(check),permissive(extends)))；
   definitely-true = extends∈anyOrUnknown ||
   assignableTo(restrictive(check),restrictive(extends))；
   两者皆非 → **保持延迟**。此前用裸 assignability 判支，把 unknown-fill 的
   `unknown extends unknown[]` 判假支导致塌缩。
2. **permissive/restrictive 实例化助手**（`get_permissive_instantiation` /
   `get_restrictive_instantiation` + ProbeMode 走查器）：TP→wildcard(顶层
   函数型)/TP→去约束克隆。仅替换 Union/Intersection/Array-Object/Tuple/
   Conditional(check/extends 浅换)/IndexedAccess；条件臂不重解析。
3. **创建期上下文快照**（ConditionalTypeData.creation_type_argument_stack +
   ConditionalRoot.creation_scopes）：延迟条件创建时抓取替换帧栈与作用域
   ID 链（键 = symbol ptr as usize 规避 Send/Sync）；分支最终必须解析时
   重压「当前栈未绑定的键 + 非公共后缀作用域」。分支解析结果**不写**
   resolved_*_type 单元格（它们语义是"整个条件已被判定"）。等价 Go 在每个
   延迟条件上携带 mapper。
4. **关系层双回退**（is_type_related_to 尾部）+ **推断层同根快速路径**
   （infer_from_types_inner 顶部，root 节点 id 同一 ⇒ 互推 check/extends；
   跳过带 infer 参数的根）：
   - 源侧（Go relater.go ~L3793）：未决延迟源 → 默认约束（双支联合，
     any 支按 never 略去、分布依赖根排除）。
   - 目标侧（Go relater.go ~L3580）：未决延迟目标 → 双支均需通过；
     skipTrue/skipFalse 用探针判可达性；same-root 源跳过（交给推断）。
     **注意独立于源侧门**（联合源逐成分也要进）。

分布独立性近似 `conditional_distribution_independent`：非分布式根恒可；
分布式根扫描两支顶层（并集成员/括号穿透）是否裸引用 check 参数名，
嵌套（keyof/别名调用/映射模板）不计 —— Go isTypeParameterAtTopLevel…
的语法版。

严格性守卫（防回退过宽）：b2/b5 双向仍报错（exp_c2/exu 也复核不变）。
