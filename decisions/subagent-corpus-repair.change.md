# subagent-corpus-repair 变更记录

## v1.2 · 2026-09-21

新增第 5 条硬约束与退出契约细则。背景：corpus5 波次（2026-09-20 23:56 派发，8 并发）整波耗时 3.4 小时后主 ticket 过期中止，8 个 subagent 中 3 个正常提交退出、4 个死时零提交（全部工作滞留脏工作区）、1 个全程无产出；其中 jsany agent 违反 v1.1 否决项一，自行跑了全量 corpus 并在覆写 corpus_results.csv 时被终止（transcript 证据：终止前 3 分钟内连续 3-9 秒的轮询请求）。归因：v1.1 只写了约束条款，没有可执行的派发模板，corpus5 prompt 未落实（保留了整簇批量验证步骤、只有末端一次提交点、无 CPU 上限导致 8 agent 各自 cargo 默认并行打满 24 核、无时限与熔断）。处置：新增 tools/subagent_prompt_template.md 作为唯一派发模板（主 agent 内联全文使用），加入总时长预算与 T-15 强制收尾、单根因 25 分钟熔断、Bash 连续 3 次故障即写交接退出、每根因验证通过立即 commit、验收线达成即退出、并发 ≤4 与每 agent 构建作业上限。

## v1.1 · 2026-09-20

新增否决项三：subagent 自行验证修复正确性。理由：批量验证是修复慢的另一半根因，验证结论只在主 agent 合并决策处有意义，正确性裁决收敛主 agent 形成修改与验证分离。结论改为四条硬约束。

## v1.0 · 2026-09-20

初次记录。背景：corpus3 轮次多 subagent 并行修复中，subagent 反复被平台配额终止（票据过期、600 秒无活动超时），且接手后需自行跑家族批量定位目标导致修复缓慢。据此拍板：全量验证主 agent 独占、subagent 接明确用例清单、小步提交与交接日志应对配额终止。
